# Visual direction for Barça Radar

Use alongside `video-production`, `AGENTS.md` and the active episode packet. Read `docs/video-production/creative-integrations-2026-10-28.fa.md` for researched tools and actual connection status. This skill is a planning workflow, not an installed renderer or external service connection.

1. Read the actual source/transcript before choosing a genre. Existing presenter content remains authoritative when the user selected source alignment. A format study is not permission to rewrite that speech or introduce unrelated scripts.
2. Write the visual promise in one sentence: what should a viewer understand or feel that a talking head alone does not convey? Distinguish narrative diversity (different questions and evidence) from surface variation (different colors, zooms or transitions).
3. Choose a dominant visual language per episode: studio analysis, spatial lab, archival documentary, data dossier, geographic story, or illustrated essay. Retain brand typography and restrained Barça colors; avoid making every family the same split screen.
4. Draft three representative style frames: opening, explanatory core, conclusion. Specify focal point, scale, hierarchy, negative space and whether the media are event evidence, identity reference, sourced data, schematic or generated illustration. Review at the actual target ratio and phone scale.
5. Create a shot table: source time/words → purpose → dominant subject → visual action → camera/layout → evidence/asset ID. Each shot has one useful change. Cues follow the speaker's causal sequence. Use holds when viewers need to read space, documents or charts.
6. Select tools by visual function:
   - Remotion for typography, captions, charts and assembly.
   - Figma for designing reusable frames/components; it does not set video timing.
   - Maps for place, routes and scale; retain geographic sources, attribution and render-ready assets.
   - Blender/Three for depth or viewpoint changes; keep a matching 2D orientation when it aids understanding. Render precomposited shots when that is more reliable than a live 3D browser scene.
   - Manim/Motion Canvas for a demonstrated need for geometric or explanatory animation; simpler relationships can remain in Remotion.
   - Generated imagery/motion for an identified illustrative role. Do not depict a fabricated match moment as observed evidence or regenerate the source presenter's words.
7. Preserve the active episode's voice timeline, caption pages and review state. A new image does not establish a new tactical fact. Original schematics must be labeled. A portrait from another game is identity reference, not match evidence.
8. Prototype the riskiest visual idea in a still or short clip before extending the episode. Inspect focal clarity, text/face crop, motion, transitions, caption fit and timing. Measure actual render behavior; a successful still does not establish animated render cost or output readiness.
9. Record tool/provider/model/version, source inputs, artifact location, rights, approved budget where applicable, and exact status: proposed, researched, connected, prototype-rendered or delivery-verified. Respect the user's existing authorization; do not label a repository document as an active Skill/MCP connection.

Deliver a visual brief, genre-specific style frames, a source-timed shot table, a justified tool choice, and evidence from the actual prototype. Keep research and decisions in GitHub when authorized. Social publication is separate.

For open-source timeline/compositing tools, read `docs/video-production/open-source-editors-2026-10-28.fa.md` and its evidence. An editor UI, MCP source module or headless JSON runner does not prove full video export. For continuation use `CLOUD_GUIDE.fa.md` and the state ledger.
