## بررسی‌ها و شواهد

- ۱۸ آزمون Python ابزارهای render و سه آزمون JavaScript اعداد موفق‌اند؛ چهار آزمون sync مخزن اصلی نیز موفق‌اند: مجموع۲۵ آزمون.
- TypeScript و bundle از مسیر `studio/` موفق شدند. پنج دارایی کاتالوگ از نظر metadata لازم، مسیر و checksum بررسی شدند.
- فریم‌های واقعی نمونهٔ عکس در هر دو نسبت تصویر و هفت فریم شورت تطبیقی، شامل شروع، پرس، پدری، خط دفاع، یامال، مجری و پایان باز شدند. اشکال لایه‌بندی تصویر contain در preview اصلاح و فریم تازه بررسی شد.
- کلیپ گذار تطبیقی از فریم۳۳۰تا۵۱۰، به‌صورت proxy با ابعاد540×960 و مدت6.037s رندر شد؛ decode کامل و H.264/yuv420p/30fps موفق، سطح صدا−16.00LUFS و−3.11dBTP بود. این اندازه‌گیری فقط برای همان کلیپ است، نه مستر کامل.
- نام نمایشی عکس گروه بارسلونا۱۹۷۳، از نام فرد به «Barcelona · Schiphol 1973» تغییر کرد؛ عنوان آرشیوی سند شناسایی فرد جلوی عکس نیست. تصویر کرایف۱۹۸۸ با تاریخ خودش نگه داشته شد.
- نسخهٔ جدید SRT/قاب با artifact قبلی یکسان نیست. [تحویل قدیمی](../barca-radar/clasico-source/delivery.json) به commit `d52a6d8` تعلق دارد؛ اندازه‌گیری آن برای این کد دوباره استفاده نمی‌شود.

## ادامه در Cloud

1. [راهنمای عکس‌ها](photographic-production.fa.md) و manifest قسمت را بخوان؛ متن ویدیوی واقعی مبناست.
2. برای دارایی تازه، تصویر و منشأ و تاریخ را بررسی کن، کاتالوگ و credits را به‌روزرسانی کن. candidate با verified فرق دارد.
3. رسانهٔ مجری را در مسیر ignored بازیابی و hash آن را بررسی کن؛ `episode.py --mode preview --check-media --build-captions` را اجرا کن.
4. از `studio/` typecheck/bundle، فریم گذار و کلیپ نمونه بساز. پیش از release، موارد unresolved واقعاً رفع شوند.
5. workflow `render-visual-models.yml` برای دمو بدون ویدیوی خصوصی است؛ `render-source-short.yml` برای منبع مجری، ورودی Drive در runtime می‌خواهد.
6. نتیجهٔ واقعی Actions و فایل دانلودشده در گزارش جدا ثبت شود؛ push یا dispatch به معنی تحویل موفق نیست.

ادغام همهٔ engineهای قدیمی، تعمیم manifest به تمام۲۳قسمت، feed آژانس، مدل جداسازی جدید و مستر بلند هنوز انجام نشده‌اند. آن‌ها پیش‌نیاز این پنج شیوهٔ عکس نیستند. ارتقای retention/CTR اندازه‌گیری نشده است.
