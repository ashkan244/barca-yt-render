# راهنمای تولید حرفه‌ای Barça Radar برای ادامه در Cloud

تاریخ تحقیق و پیاده‌سازی: ۲۶ اکتبر ۲۰۲۶. هدف این راهنما، قالب‌های تدوین و تولید ویدیو است؛ پیشنهاد «مدل ویدیویی» لزوماً به معنی نصب مدل مولد یا تغییر موتور پروژه نیست.

## از اینجا شروع کن

1. آخرین تصمیم کاربر و بستهٔ قسمت را بخوان. برای خروجی فعلی، [clasico-source](../barca-radar/clasico-source/README.md) و گفتار فایل واقعی مبناست. [بستهٔ PSG](../barca-radar/psg-4-2/README.md) سند جداست.
2. [تحقیق و شواهد](research.fa.md) را برای دلیل انتخاب‌ها و دامنهٔ بررسی بخوان.
3. [راهنمای قالب‌ها](format-playbook.fa.md) را برای ساختار روایت/تصویر انتخاب کن.
4. [ابزارها](../../tools/video/README.md) و [مهارت قابل استفادهٔ مجدد](../../.agents/skills/video-production/SKILL.md) مسیر عملی کار را مشخص می‌کنند.

## آنچه واقعاً به پروژه اضافه شده

| قابلیت | فایل / ابزار | محدودیت |
|---|---|---|
| ثبت نقش، مشخصات و checksum ورودی | tools/video/media.py inspect | موضوع و صحت محتوا را حدس نمی‌زند |
| contact sheet زمان‌دار | media.py contact-sheet | جای تماشای گذار و شنیدن صدا را نمی‌گیرد |
| کات‌های نامزد | media.py cuts | نور/فلش می‌تواند تشخیص کاذب بدهد |
| پیاده‌سازی گفتار با زمان کلمه | media.py transcribe + requirements.txt | نصب اختیاری؛ نام‌ها و عبارت مبهم بازبینی می‌خواهند |
| تطبیق اولیهٔ متن و اجرا | media.py check-script | هر دو پوشش متن و اجرا بررسی می‌شوند؛ تست حقیقت یا معنا نیست |
| کنترل ساختاری و decode و loudness | media.py qc | خروجی nonzero برای خطای ساختاری؛ کیفیت زیبایی‌شناختی را خودکار تأیید نمی‌کند |
| دریافت Drive با checksum | download_drive.py | فقط فایل قابل دسترس؛ بدون استخراج auth |
| آماده‌سازی صدا و ویدیو | prepare_source.py | تایم‌لاین ثابت، بدون حذف خودکار مکث |
| زیرصدای اصلی بدون سمپل خارجی | make_score.py | انتخاب زیبایی‌شناختی اختیاری؛ مستر نهایی اندازه‌گیری شود |
| فونت محلی مجاز | public/fonts + production/fonts.ts | تغییر فونت ممکن است wrapping قدیمی را عوض کند |
| کپشن زمان‌دار با fit متن | production/Captions.tsx | ورودی باید بازبینی شود؛ نام Reviewed به معنی تأیید خودکار ASR نیست |
| برد تاکتیکی عمومی دو تیم | production/TacticalPlate.tsx | شماتیک است؛ tracking یا منبع آماری نیست |
| رندر مستقل فایل واقعی | render-source-short.yml | اجرای واقعی، دسترسی Actions و asset لازم دارد |

سه بستهٔ Remotion جدید دقیقاً با نسخهٔ فعلی 4.0.535 هماهنگ شدند: `@remotion/fonts`، `@remotion/layout-utils` و `@remotion/captions`. فایل lock به‌روزرسانی شده است. وابستگی ASR در venv جدا نصب می‌شود؛ PyAV16.0.1 به دلیل ناسازگاری نسخه19 با faster-whisper1.2.1 مشخص و آزمایش شد.

## قرارداد ورودی — مهم‌ترین اصلاح فرایند

قبل از طراحی، چهار نقش جدا ثبت شوند: ویدیوی مرجع، اجرای مجری، سناریو و خروجی. فایل Drive فعلی ابتدا از روی زمینهٔ گفتگو به PSG نسبت داده شد؛ بررسی گفتار نشان داد تحلیل تاکتیکی ال‌کلاسیکو است. پس نام فایل، طول و زمینهٔ قبلی برای تعیین موضوع کافی نیستند. این راهنما برای جلوگیری از تکرار همان اشتباه، inspect و check-script را قبل از موشن قرار می‌دهد.

## نصب و شروع مجدد در Cloud

Cloud از قبل محیط جدا دارد؛ از checkout موجود استفاده کن و بدون درخواست کاربر worktree نساز.

```sh
cd /workspace/barca-yt-render/studio
npm ci --no-audit --no-fund
npx tsc --noEmit
```

برای ASR، دستورهای venv در tools/video/README.md را اجرا کن؛ مدل‌ها و فایل‌های خام خارج از Git باشند. وجود dependency به معنی وجود فایل‌های runtime یا زنده‌بودن سرویس نیست. بعد از برگشت به Cloud باید رسانه از مسیر مجاز دوباره بازیابی/تأیید شود و Studio یا رندر دوباره شروع شود.

## ارزیابی پس از انتشار

به‌جای فرض «افکت بیشتر = retention بهتر»، فرضیهٔ مشخص بنویس: آیا توضیح مرحله‌ایِ پرس نسبت به متن ثابت، فهم و ماندگاری را بهتر می‌کند؟ سپس فقط همان متغیر را در نمونه‌های قابل مقایسه بررسی کن. داده‌های intro، dip و spike را از YouTube Analytics واقعی بخوان. spike می‌تواند بازدید مجدد به‌خاطر جذابیت یا ابهام باشد؛ به‌تنهایی معیار موفقیت نیست. هیچ درصد بهبود از این تحقیق اندازه‌گیری نشده است.
