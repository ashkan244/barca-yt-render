# قرارداد فایل اصلی و تحویل به GitHub Actions

## وضعیت ورودی در ۲۶ اکتبر ۲۰۲۶

پوشهٔ Drive پاسخ موفق داد و یک فایل با نام **Barca radar clip 3** دریافت شد. فایل حدود 123.5MB، مدت 175s (۲:۵۵)، تصویر 720×720، HEVC با نرخ اسمی 30fps و صدای AAC استریو 44.1kHz دارد. مشخصات و checksum در [source-metadata.json](source-metadata.json) ثبت است.

کاربر تأیید کرد این فایل **اجرای شورت** است. اجرای بلند جداگانه ارسال خواهد شد. مدت 175s طول منبع است و به معنی تعیین مدت نهایی شورت نیست. تایم‌لاین HO موجود 448.19s فقط مرجع برنامه‌ریزی بلند است؛ تفاوت طول دو فایل، نشانهٔ ناقص‌بودن اجرای شورت نیست. محتوای گفتار شورت هنوز پیاده و تطبیق داده نشده است.

فایل خام در محیط فعلی، خارج از checkout نگهداری می‌شود؛ این محل تحویل پایدار برای runner گیت‌هاب نیست. فایل، لینک Drive، کوکی، تأییدیهٔ دانلود و کلید رمزگذاری در Git ثبت نمی‌شوند. این بسته فقط مشخصات غیرمحرمانه و برنامه را منتشر می‌کند.

## قرارداد جایگزینی

۱. **Probe:** مدت، اندازه، نرخ واقعی/متغیر فریم، چرخش، ترک صوت و خطای decode بررسی شود. خروجی 1080p جزئیات واقعیِ ورودی 720px را بیشتر نمی‌کند؛ قاب و crop بر این اساس انتخاب شوند.
۲. **Content:** گفتار اجرای بلند با script.en.md تطبیق داده شود. برای شورت، متن و EDL از فایل مستقل شورت استخراج شود؛ هیچ بازهٔ L16–L19 از تایم‌لاین بلند به آن تحمیل نشود. retake، تکرار و پرش مشخص شود. بخش‌های نرسیده یا متفاوت صریحاً ثبت شوند. transcript تازه از روی برنامه‌ریزی جعل نشود.
۳. **Edit:** از ابزار tools/host/radar-edit.mjs و ورودی مطابق قراردادش استفاده شود؛ اسکریپت episodes/host و کلمات Whisper لازم دارد و این ورودی‌ها باید موجود یا از اجرای واقعی تولید شوند. ابزار تکرارها و تطبیق کلمات را تقریبی تشخیص می‌دهد؛ خروجی دستی بازبینی شود.
۴. **Normalize:** در صورت نیاز HEVC به H.264 سازگار و CFR30 تبدیل شود؛ صدا و چرخش حفظ شود. این تبدیل فقط روی فایل تازهٔ تولیدی انجام شود، نه overwrite ورودی. صدای مجری در تدوین یک بار استفاده شود تا ویدیوی muted و Audio جدا هم‌زمان صدای تکراری ندهند.
۵. **Timeline:** HO.edit.json و ارجاع‌های makeT به کلمات تازه تطبیق داده شوند؛ شاخص کلمهٔ قدیمی برای متن تازه ممکن است clamp شود و به‌ظاهر کار کند اما زمان غلط بدهد. تمام خط‌ها، مرز فصل‌ها و پایان بازبینی شوند.
۶. **Path:** مسیر runtime قالب بلند `studio/public/host/HO/HO-edit.mp4` است. شورت از اجرای مستقل دریافت‌شده و EDL مخصوص خودش استفاده می‌کند؛ ورودی و تایم‌لاین آن از HO-edit جدا نگهداری شوند. مسیر پیشنهادی خروجی تدوین شورت `studio/public/host/HO/HO-short-edit.mp4` است و هنوز ساخته/به composition متصل نشده. صوت و تصویر باید دقیقاً همان cut را داشته باشند. فایل جایگزین فقط وقتی drop-in است که طول و تایم‌لاین واقعاً یکسان باشند.
۷. **Transfer:** runner جداست؛ رسانه باید پیش از dispatch با روش موجودِ قطعات رمزگذاری‌شده یا کانال مجاز و قابل دسترس runner تحویل داده شود. فایل local به‌تنهایی برای Actions کافی نیست. طرح رمزگذاری موجود AES-256-CBC/PBKDF2 است؛ در صورت استفاده از همین قرارداد، فایل تازه جدا آماده و قبل از جایگزینی نسخهٔ قبلی، decrypt و checksum محلی بررسی شود. کلید فقط در تنظیم امن GitHub با نام HOST_KEY قرار بگیرد؛ هیچ مقدار یا رمز تازه‌ای در چت/کد نوشته نشود. اگر secret از قبل موجود و قابل استفاده است همان binding حفظ شود.

فایل ورودی تازه هنوز normalize، cut، encrypt یا upload نشده است. در این مرحله صرفاً بستهٔ برنامه‌ریزی به Git می‌رود.

## آنچه workflow فعلی دارد

`.github/workflows/render.yml` با workflow_dispatch اجرا می‌شود و روی push ساده اجرا نمی‌شود. Node22، npm ci، bundle، کش صوت، مرور ترکیب‌ها برای chunkها، رندر موازی، concat، loudness و QC sheet دارد. در رندرِ دارای presenter، HOST_KEY برای رمزگشایی قطعات لازم است. وضعیت secret در GitHub در این کار بررسی نشده است.

- `composition`: برای بلند HO-RADAR موجود است. HO-RS1-CARRY پیشنهادی قبل از ثبت در Root قابل اجرا نیست.
- `code`: برای صدای مجری **خالی**؛ مقدار دادن این فیلد مسیر Kokoro را فعال می‌کند و برای این پروژه جایگزین گفتار کاربر نیست.
- `chunks`: برای smoke ابتدا ۱ و برای خروجی بلند پس از بررسی منابع، ۴ تا ۱۰؛ تعداد زیاد لزوماً سریع‌تر یا ارزان‌تر نیست. اگر workflow فعلی امکان بازهٔ کوتاه نمی‌دهد، smoke محلی با CLI انجام شود؛ عدد chunk مدت را کم نمی‌کند.
- `crf`: مقدار آغازین ۲۰.
- `prep`: برای بلند معمولی خالی. ماتینگ یک مرحلهٔ اختیاری است، نه لازمهٔ هر شورت. مثال فعلی HK را با HO اشتباه نگیریم.

معادل پیشنهادی پس از تأمین prerequisites و در صورت وجود دسترسی gh:

```sh
gh workflow run render.yml --repo ashkan244/barca-yt-render --ref main \
  -f composition=HO-RADAR -f code= -f chunks=4 -f crf=20 -f prep=
```

این فرمان هنوز اجرا نشده است. قبل از dispatch، ref باید شامل کد نهایی و دارایی‌های قابل بازیابی باشد. بعد از dispatch، run ID ثبت، پایان واقعی jobها دنبال، artifact صحیح همان run دریافت و محتوا بررسی شود. سبزبودن job به‌تنهایی بررسی بصری/صوتی را جایگزین نمی‌کند.

## آزمون قبل از رندر کامل

از studio با dependencyهای نصب‌شده:

```sh
./node_modules/.bin/tsc --noEmit
./node_modules/.bin/remotion bundle src/index.ts --out-dir=build
./node_modules/.bin/remotion compositions build --browser-executable=/usr/bin/chromium
```

مسیر Chromium بالا مربوط به محیط فعلی است؛ runner گیت‌هاب باید مرورگر قابل استفادهٔ خودش را داشته باشد. پس از تطبیق زمان‌ها، یک بازهٔ ۲۰–۳۰ثانیه‌ای از صحنهٔ carry با concurrency2 رندر شود. فریم‌های دقیق از EDL تازه محاسبه شوند؛ زمان مرجع فعلی را کورکورانه به فایل تازه اعمال نکنیم. قطع صدا، لب، فونت، asset404 و کیفیت upscale بررسی شود.

در onboarding دریافت فونت مسدود بود؛ بعداً دسترسی Drive برقرار شد ولی این اتفاق به معنی تأیید مجدد بارگیری فونت یا رندر نیست. شبکه و browser مجدداً با عملیات واقعی بررسی شوند. اگر خروجی از قبل معتبر است فقط با تغییر مؤثر دوباره build/render شود.

## نکات خاص workflow برای این قسمت

- شاخهٔ metadata فعلی تنها وقتی spec هم‌نام در src/episodes/specs وجود دارد، export و thumb را انجام می‌دهد. ترکیب HO-RADAR/thumb در Root به‌تنهایی وجود metadata artifact را تضمین نمی‌کند؛ برای این قسمت export مشخص لازم است.
- شکست thumbnail در workflow فعلی با `|| true` نادیده گرفته می‌شود. برای تحویل این قسمت باید وجود و صحت تصویر واقعاً بررسی شود.
- استوری‌بورد HTML با رندر Remotion فرق دارد و جای smoke نهایی را نمی‌گیرد.
- bundle میزبان رسانهٔ عمومی را کپی می‌کند؛ حذف footage از artifact bundle در workflow موجود حفظ شود. فایل خام یا رمزگشایی‌شده داخل artifact یا Git نرود.
- اسکریپت qc-radar در وضعیت فعلی یک فریم از ۶۰٪ هر جمله می‌گیرد؛ همهٔ گذارها و مرزهای cut باید جدا بررسی شوند.
- هیچ dispatch یا انتشار YouTube در این مرحله انجام نشده است.
